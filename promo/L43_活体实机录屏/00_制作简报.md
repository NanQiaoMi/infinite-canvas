## 1. 项目事实卡（写稿只能引用以下已核实事实）

### 1.1 身份

- 项目名：**无限画布（infinite-canvas）**，仓库 `basketikun/infinite-canvas`，**MIT License**，开源免费（`README.md:25`、`README.md:218`）。
- 定位：**面向图片创作的开源工作台**。把画布编排、AI 图片生成、参考图编辑、对话助手、提示词库和素材沉淀放在同一个界面里（`README.md:25`）。
- 版本现状：`VERSION` = **v0.20.0**（2026-10-10 发布）；当前分支 `feat/conversation-agent` 领先 v0.20.0 **119 个提交**（`git rev-list --count v0.20.0..HEAD`），**尚未发版、无 v0.21 tag**。宣传口径统一写「本次更新 / 新版本开发中」，或使用占位符 `{{版本号}}`、`{{发布状态}}`。
- 开发阶段声明：项目自述「不保证历史数据兼容」（`README.md:27-30`）。不写「企业级」「零故障」「生产级稳定」。
- 技术栈：前端 Vite 7 + React Router 7 + TypeScript + Ant Design + Tailwind + Zustand；浏览器直连 OpenAI 兼容接口；本地数据在 IndexedDB / localforage；另有 Bun + SQLite 服务端模式（`README.md:12-15`、`README.md:157-175`）。
- 安全口径：AI API Key、Base URL、画布、素材和生成记录**默认保存在浏览器本地**（`README.md:131`）；只有服务端模式才把 Key 放服务端。不写「绝对安全」。

### 1.2 既有核心能力（不是本次新增，但片子里要交代「这是什么产品」）

- 工具协议：`generate_image`、`edit_image`、`apply_prompt`；支持文本 `tool` 代码块协议与原生 function calling，管理后台可按渠道选「自动 / 文本 / 原生」（`zh-CN.ts:710+` 的渠道 `toolProtocol` 文案）。
- 多轮多步任务拆解、ReAct 自循环**最多 8 轮**（`web/src/lib/conversation-agent/runtime.ts:269` `maxRounds ?? 8`）。
- 比例/张数追问继承（「再来 8 张横屏的」）、参考图改图（「把背景改成深蓝色」）、GIF 动图。
- `⌘K / Ctrl+K` 命令面板、`/prompt` `/image` `/edit` `/new` `/help` `/model` 命令（`zh-CN.ts:901-958`）。
- Artifact 大图预览面板、多选对比、批量作为参考图、提示词库入口、模型选择器、执行步骤时间线、图片骨架屏与阶段文案（`chat/index.tsx`、`components/`）。
- 界面：Claude 风格两栏/控制台形态；实测设计 token：页面底色 `#faf9f5`、侧栏 `#f2efe8`、侧栏宽 276px（`web/src/pages/chat/index.tsx:683-684`）。
- 关键数字：单次生成张数上限 **12**（`tools.ts:32` `maximum: 12`）。

**B. 画布 AI 助手与批量生成**

- 画布页内置 AI 对话面板，原生画布工具体系：`canvas_create_image_node`、`canvas_batch_generate_nodes`、`canvas_create_text_node`、`canvas_update_node`、`canvas_connect_nodes`、`canvas_delete_nodes`、`canvas_focus_nodes`、`canvas_get_context`（`web/src/lib/conversation-agent/canvas-tools.ts`）。
- 批量上限 **12 张**；10–12 个节点自适应 **4 列 × 3 行**网格排布（`web/src/lib/canvas/canvas-layout-planner.ts`：`count <= 9 ? 3 : 4` 列；`canvas-tools.ts:266` `tasks.slice(0, 12)`）；4 张 2×2、6–9 张 3 列。
- 批量排布从串行等待升级为 `Promise.all` 并发；ReAct 循环有「生成总张数熔断刹车」，达成张数即停。
- 画布与普通对话**物理隔离**（scope = chat / canvas + canvasProjectId），互不串图；步骤按 threadId / turnId / itemId 归属，后台任务不丢。

**C. 生成稳定性、队列与可观测性（本次工程含金量最高的部分）**

- 后端异步任务队列：HTTP 202 + `GET /v1/tasks/{id}` 状态轮询 + `DELETE` 取消；展示排队位置、预估倒计时、绘制进度（`web/src/services/api/image-queue.ts`）。
- 全局任务管理器 `useImageTaskStore`：页面刷新自动恢复未完成任务并继续轮询；向下兼容 HTTP 200 同步网关（`web/src/stores/use-image-task-store.ts`）。
- 客户端并发上限 **4 个生成槽位**，其余排队（`web/src/pages/image/index.tsx:241`）；1.5s 内相同提示词去重、生成期间互斥（同文件 `:336`、`:344`）。
- 单次接口上限 4 张 → 超过自动拆批（`splitCountIntoChunks`，`web/src/services/api/image.ts:812`）并发请求并汇聚，根除 422（`n: Input should be less than or equal to 4`）。
- 稳定性：对话流式请求 **120s 空闲超时**（`web/src/services/api/image.ts:123`）；网络抖动/5xx/超时自动重试（最多 2 次，步骤里显示「网络异常，等待重试（1/2）」）；失败自动降级换同能力模型再试一次；失败卡片「重试」就地重来（`zh-CN.ts:939-944`、`generation-retry.ts`）。
- 生成诊断面板：最近 **120 条**记录、持久化 **500 条 / 最近 7 天**（`web/src/lib/conversation-agent/diagnostics.ts:18-19`）、7 天失败率趋势、渠道健康检查、一键复制诊断报告。
- `CHANGELOG` 记录：6 张批量生成从「成功 3 / 失败 3（上游限流）」提升到「6 张全部成功」——这是**仓库内记录**，片子里不要当成绝对承诺。

**D. 工作台视觉统一、字体、服务端模式与后台**

- 生图工作台 / 视频创作台 / AI 对话三处统一为 Claude 风格设计语言（暖白、扁平侧栏、无卡片分区、圆角输入、悬浮毛玻璃操作条、骨架/空状态）；实测：`/image` 侧栏 252px、`#f2efe8`，能力 chip `IMAGE`（`web/src/pages/image/index.tsx:640`、`:643`）。

- GIF 动图：`gpt-image-2.6` 系列，2–16 帧、1–20 fps、默认 9 帧 / 5 fps（`zh-CN.ts:188-194`）。
- 默认生图模型升级为 `gpt-image-2.6`；AI 自主决定画幅（开阔横向 1536×864、人物立绘 864×1536、特写 1024×1024）。

### 2.2 本片适配规则（L43 × 无限画布，17 条，全部强制执行）

1. **两层分辨率是本体**：真实产品 UI 用 HTML/CSS/SVG **重绘**（零截图、零录屏贴图），高分辨率、文字锐利；像素层只属于小方、它的道具、轨迹和尘土。两种分辨率的硬边冲突就是本片的「look」。
2. **窗口浮在墙纸上**：暖米色渐变墙纸 + 轻微暗角；应用窗口圆角 12px、软阴影；相机 zoom ≥ 1，任何镜头都不出现窗口外的「屏幕之外」。
3. **UI 尺寸基准**：窗口设计尺寸 **1366×768 CSS px**（16:9 精确）；在 1920×1080 画布内等比缩放并居中，默认全窗可见（约 1536×864 屏幕像素）。相机推近范围 1.0×–2.2×。
4. **重力 = UI 的上边缘**：小方只站在真实元素的上边缘（顶栏底边上方、欢迎标题顶边、输入框顶边、消息气泡顶边、工具卡顶边、结果卡顶边、队列胶囊顶边、画布节点顶边、按钮顶边、成品海报顶边、窗口标题栏顶边）。位置**每帧由 DOM 测量**（`offsetParent` 链累加，不受相机 transform 影响），不许手写坐标。
5. **像素网格神圣**：小方与道具共用一套正方形像素格，基础像素单位 `u = 8 CSS px`（窗口内）；落位坐标量化到 `u`，运动按 30fps 阶梯；`image-rendering: pixelated`，禁止抗锯齿、禁止半像素。
6. **两个演员，永远没有手**：光标 = 用户（平滑弹簧路径、点击有推动感、从不瞬移）；小方 = 软件（读、想、做、等、救的化身）。任何用户操作必须在画面里可见（光标路径 / 点击 / 键击 HUD）。
7. **因果必须闭合**：小方每个动作都要触发真实 UI 状态变化（跳上输入框 → 聚焦；按住发送 → 消息发出；推节点 → 网格排布；扑向失败卡 → 重试成功）。UI 动效只用产品自己会有的（弹层 pop、卡片淡入、步骤展开），不发明产品没有的花哨转场。
8. **颜色纪律**：UI 只用产品真实浅/深主题色（`#faf9f5` / `#f2efe8` / stone 系 / `#171717` 主按钮）；**小方独占饱和橙 `#E8703A`**（产品 UI 中不出现该色）；叠加层只用中性毛玻璃 + 至多一个产品已有强调色。**深色主题切换是剧情事件**：第 4 幕切换时全片短暂变暗、音乐低通、再切回。
9. **字体**：UI 用产品字体（Cascadia Mono 英数 + 方正小标宋中文，@font-face 指向仓库 `web/public/fonts/`，附回退栈）；标题与正文全部按真实产品字号（11/12/13/14/16/18px，欢迎标题 28px 级）。
10. **信息层只有四样**：左上章节胶囊（01–04，毛玻璃）、右下 KeyCastr 风格键击 HUD、底部字幕胶囊、右上可选「▶▶ 4×」时间标签。**除这四样和窗口 chrome 外，不叠加任何装饰层**；不做片头大标题卡（片名用 diegetic 方式出现在 `/chat` 欢迎标题上）。
11. **字幕**：底部居中毛玻璃胶囊，最多 2 行、每行 ≤ 18 个汉字；不遮被讨论的元素、不压小方；每条停留 ≥ max(1.8s, 阅读时间 + 0.6s)，阅读时间按「字数 × 0.18s」估算；同一时刻最多 1 条。
12. **相机语法**（L43 §6 原表，按需选用）：推近光标/插入点（push-in）、静止慢漂（drift）、跨窗甩镜（whip-pan，方向性动态模糊只加在未变换的外层）、推近+暗角冻结（spotlight freeze）、窗格间移焦（rack focus，绝不虚化要读的字）、拉回到整窗（pull back）、跟着小方沿列表/网格走（follow）。
13. **本片采用的 L43 原生动作**：match-cut origin（小方从顶栏 logo 内三角的像素块剥落并爬出）、diegetic title（`/chat` 欢迎标题「无限画布 Agent」）、moving floor（骑光标/发送的消息/进度条/队列胶囊）、time-lapse tag（刷新恢复任务时的 ▶▶ 4×）、spotlight freeze（片尾开源承诺）、the film changes state（第 4 幕深浅主题切换）、cell division（12 个画布节点的像素分裂）、cursor & mascot as characters（光标戳小方、小方挥手）、karaoke-ball words（数字 12 / 4 / 7 逐字跳跃）。
14. **运动质量**：30fps；UI 动作按 1 帧做；小方有预备下蹲、起跳拉伸、收腿、落地挤压 + 阻尼回弹 + 尘土；待机呼吸（随节拍微挤压）、不规则眨眼；走路双腿交替、翻转朝向；眼睛承担表演（中立/左/右/上/下/瞪大/开心/闭眼/眨眼）；手臂下垂/欢呼/挥手/抱道具/推。
15. **声音是两层**：hi-fi 层（立式钢琴、低音提琴、刷鼓、钟琴）是世界；chiptune 方波/脉冲是小方。Foley：键盘 thock+click（带人类节奏抖动）、触控板点击、面板 swish、弹层 pop、通知 chime、快门（截图感）、小方脚步/起跳/落地 8-bit。**无旁白、无 TTS**；关键承诺前 0.6s 静音到房间底噪；混音目标 −14 LUFS。
16. **深度只用两样**：rack focus（只虚化不读的窗格）和暗角聚光；**绝不虚化要读的文字**；动态模糊只在甩镜时加。
17. **陷阱清单**（逐条自检）：不出现产品没有的按钮/文案/快捷键；小方不漂浮、不挡字、不压字幕；不出现手；不出现真实截图/录屏；不出现第三方品牌；像素不抗锯齿；同一镜头里不出现第二种饱和色；产品名不被音效盖住。

### 2.3 引擎与实现规范（给 03，W3 必须落成可执行约束）

- **交付物形态**：单个自包含 `index.html`（原生 HTML/CSS/SVG + 少量 Canvas 画小方）；零外部依赖、零 CDN；字体通过相对路径 `web/public/fonts/` 的 @font-face 引用并附回退栈（用本地静态服务器打开，例如 `python3 -m http.server` 或 `bunx serve`）；不得依赖外网。
- **分层**：`#wallpaper` → `#window`（chrome + `.app` 真实 UI 层）→ `.pixel-layer`（小方/道具/尘土 canvas）→ `.hud`（章节胶囊/键击/字幕/时间标签）。
- **相机**：单一 `.stage` 容器 `transform: translate() scale()`；相机关键帧（时间 → x/y/zoom）用弹簧缓动；**测量必须走 `offsetParent` 链**（不受 transform 影响），目标元素统一带 `data-anchor="xxx"`。
- **时间轴**：总长 `T = 90.0s`；`seek(t)` 纯函数式渲染（同 t 必得同画面）；`?t=12.5` 定格；空格暂停/继续；默认循环；`?mute=1` 静音。
- **确定性**：禁止 `Math.random`；随机一律 `mulberry32(seed)` 且只在启动时生成一次；CSS 动画一律不用（全部由 JS 时间轴驱动，保证可定格、可逐帧导出）。
- **小方渲染**：12×12 像素矩阵（字符串数组），Canvas2D `imageSmoothingEnabled = false`；`u = 8`；姿势/表情/道具矩阵预置；位置按 `Math.round(v / u) * u` 量化。
- **UI 状态机**：每个镜头是一个 `state` 对象（页面、可见元素、文案、节点、消息），时间轴事件表切换；观众看到的 UI 必须是从 §1.6 逐字来的。
- **音频**：WebAudio 全合成（无外部音频文件）；事件表 `{t, type, params}`；音乐 72 BPM、两层；另提供 `renderAudio()` 用 `OfflineAudioContext` 导出 90s WAV，供逐帧渲染后混流。
- **性能预算**：1080p 30fps；单帧 JS ≤ 8ms；DOM 每帧更新最小化；大列表/节点用 transform 位移，不改布局。
- **导出流程**：本地静态服务器 → 浏览器验收（`?t=` 逐段定格）→ Playwright/Puppeteer 逐帧截图（30fps×90s = 2700 帧）→ ffmpeg 合成 `mp4`（H.264, yuv420p）→ 与 `renderAudio()` 导出的 WAV 混流；备选：OBS/QuickTime 录屏（非确定性，仅兜底）。

### 3.7 声音设计（03 要给可执行参数，02 要给点位表）

- **配乐 72 BPM**，两层：
  - hi-fi 层：立式钢琴（主角）、低音提琴拨弦（第 2 幕进入）、刷鼓（第 1 幕后段进入）、钟琴（开场/片尾点音）。
  - chiptune 层：方波/脉冲，只在小方「说话」/跳跃/落地/开心时出现；第 2 幕与 hi-fi 对答，第 4 幕合奏。
- **段落处理**：开场只有房间底噪 + 钟琴单音；第 3 幕网络异常时鼓组全停、只剩机械声与心跳感低音；重试成功后音乐回来但更轻；主题切换时整体低通（约 800Hz）；片尾留 pad + 一声回车铃。
- **Foley 点位**：键击（逐键，力度 ±15% 抖动）、点击、面板 swish、弹层 pop、通知 chime、刷新 whoosh、小方脚步（走一步一个 8-bit tick）、起跳/落地、尘土、睡觉 Z 音。
- **静音点**：第 3 幕「网络异常」出现的 0.6s、片尾 spotlight 前 0.6s，降到房间底噪。
- **禁止**：罐头史诗配乐、女声吟唱、TTS、任何真实录音素材（全部合成）。
- **交付**：03 里给 WebAudio 合成参数 + `renderAudio()` 导出 WAV 的规范；混音目标 −14 LUFS。
