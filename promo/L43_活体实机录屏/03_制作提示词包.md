## §0 怎么用这份文件

### 0.1 一句话流程

**复制 §2 主控提示词 → 得到 `index.html` 骨架（可运行、可定格）→ 按 §3 逐镜提示词一轮一轮把镜头补到 02 的水准 → 用 §10 验收 → 用 §11 渲染出 1920×1080 / 30fps / 90.0s 的 mp4，并与 §8 导出的 90s WAV 混流。**

### 0.2 四种用法

| 用法 | 适合 | 怎么用 |
|---|---|---|
| **A. 一把梭** | 上下文足够大的模型（Opus 5.5 级），要一次出可运行骨架 | 复制 §2 整段 + §3 的全部镜头段落，一次性投喂；模型输出单个 `index.html` |
| **B. 分幕生成** | 模型单次输出受限（约 30k tokens 内） | 先只投 §2 得到骨架，再按 §3 的幕（S01–S0x / 第 1 幕 / 第 2 幕 / 第 3 幕 / 第 4 幕 / 片尾）分 6 轮增量补丁 |
| **C. 逐镜迭代** | 想把某几镜做到位 | 保留已生成文件，每轮只贴 §3 的单镜提示词 + 「只改这一镜，其余不动，返回完整文件」 |
| **D. 收尾修复** | 已能跑但验收不过 | 贴 §10 未勾选项 + §9 负面清单 + 具体失败截图描述，要求定点修复 |

> 每轮投喂都必须**附带当前 `index.html` 全文**（用 B/C/D 时），并要求模型「返回完整文件，不要省略、不要用 `// ...` 占位」。

### 0.4 术语表

| 术语 | 含义 |
|---|---|
| **窗口（window）** | 画面里浮在墙纸上的产品窗口，设计尺寸 1366×768 CSS px |
| **舞台（stage）** | 1920×1080 的成片画布，相机变换作用在它上面 |
| **锚点（anchor）** | 真实 UI 元素上的 `data-anchor="xxx"`，小方只站在它的**上边缘** |
| **小方** | 原创 12×12 像素小人，软件的化身；饱和橙 `#E8703A`，全片只有它用这个色 |
| **光标** | 用户「你」；平滑弹簧路径，从不瞬移 |
| **px（窗口坐标）** | 1366×768 坐标系里的像素，`u = 8` 即一个像素格 |
| **屏（屏坐标）** | 1920×1080 坐标系；窗口等比放大 1.12445× 后居中（1536×864） |
| **帧（frame）** | 30fps 下的一帧；第 `f` 帧对应 `t = f / 30`，全片 2700 帧 |
| **seek(t)** | 纯函数渲染入口：给定秒数 `t`，把整部片子渲染成那一秒的画面，不依赖真实时间 |

### 1.2 层级结构（DOM 骨架，必须遵守）

```text
body
└─ #viewport            （1920×1080 视口，overflow:hidden；成片画布）
   ├─ #camera           （相机变换层：transform: translate(-cx,-cy) scale(zoom)）
   │  └─ #stage          （1920×1080 固定尺寸）
   │     ├─ #wallpaper   （暖米色渐变 + 暗角 + 噪点，绝对定位铺满 stage）
   │     └─ #window      （1366×768 设计尺寸；position:absolute; left:191.625px; top:108px;
   │        │             transform: scale(1.12445); transform-origin: 0 0;
   │        │             border-radius:12px; box-shadow:...; overflow:hidden）
   │        ├─ .window-chrome   （三枚交通灯圆点 + 居中细体标题「无限画布」）
   │        ├─ .app              （真实 UI 层：顶栏 / 各页面 .page）
   │        └─ #pixelLayer       （1366×768 canvas，画小方/道具/尘土；
   │                               position:absolute; inset:0; pointer-events:none;
   │                               image-rendering:pixelated）
   └─ #hud                （1920×1080 覆盖层，不随相机缩放）
      ├─ .chapter-pill    （左上：01–04，毛玻璃）
      ├─ .key-hud         （右下：KeyCastr 风格键击）
      ├─ .caption-pill    （底部居中字幕）
      └─ .timelapse-tag   （右上：▶▶ 4×，可选）
```

**为什么窗口要 `left:191.625px; top:108px; scale(1.125)`**：1366×768 × 1.125 = 1536.75×864，居中放进 1920×1080 后横向余量 192px、纵向余量 108px，正好是简报 §2.2-3 的「约 1536×864 屏幕像素」。窗口与舞台的坐标换算必须走同一组常量，禁止各处散写魔法数字。

```js
// §1.2 常量（实现时原样使用）
const FILM_W = 1920, FILM_H = 1080, FPS = 30, TOTAL = 90.0;
const WIN_W = 1366, WIN_H = 768, U = 8;              // U = 像素格单位（窗口坐标）
const WIN_SCALE = 1.125;                              // 02 §1.3：×1.125 放大，屏幕约 1536×864
const WIN_LEFT = (FILM_W - WIN_W * WIN_SCALE) / 2;    // 191.625（02 记「约 192」）
const WIN_TOP  = (FILM_H - WIN_H * WIN_SCALE) / 2;    // 108
const CHROME_H = 34;                                  // 02 §1.2：窗口标题栏 34px
```

### 1.6 确定性要求（本片能不能「逐帧导出」的前提）

1. **唯一时间来源**：`seek(t)` 的入参。全片不允许 `Date.now()`、`performance.now()`、`requestAnimationFrame` 的时间戳参与渲染；播放循环只负责把「当前播放时刻」换算成 `t` 再调 `seek(t)`。
2. **纯函数**：同一 `t` 连续调用两次，得到的 DOM/canvas 状态必须逐像素一致（`?t=` 两次刷新截图一致，是验收项）。
3. **随机只有一个入口**：`mulberry32(seed)`，种子固定（推荐 `SEED = 0x1F2E3D4C`）。随机只在**启动时**消费一次，用于生成静态道具/尘土/星星参数表；渲染期不允许再取随机数。需要每帧抖动时，用纯函数 `hash01(i) = (Math.sin(i * 12.9898 + seed) * 43758.5453) % 1` 或直接查启动时生成的表。
4. **禁用 CSS 动画/过渡**：`animation`、`transition`、`@keyframes` 一律不得参与画面（毛玻璃等静态样式可以用）。所有动效由 `seek(t)` 计算后写到内联 `style`。
5. **量化**：小方与道具的位置按 `Math.round(v / U) * U` 量化到像素格；时间量化到 1/30s（`f = Math.round(t * FPS)`）。
6. **定格与调试参数**：`?t=12.5` 定格在第 12.5s；`?mute=1` 静音；空格暂停/继续；默认循环播放；`?debug=1` 显示帧号/耗时（可选，默认关）。

## §2 主控提示词（一把梭，完整可复制）

### 2.2 主控提示词正文

```text
[BEGIN MASTER PROMPT]

# 一、角色

你是一名同时具备三种能力的前端工程师：
1. 前端动效工程师：熟练用原生 HTML/CSS/SVG + Canvas2D 写「可定格、可逐帧导出」的时间轴动画；
2. 技术美术：能把一个真实产品的界面按设计 token 精确重绘，能把像素小人做成有表演的动画；
3. 声音设计师：能用 WebAudio 纯合成做出 Foley 与两层配乐，并能离线渲染成 WAV。

你的工作成果不是一段 demo 代码，而是**一支 90 秒的产品宣传片的可运行母版**：任何人打开它、拖到任意一帧、定格截图，得到的都应该是成片该有的那一帧。

# 二、任务

为开源项目「无限画布（infinite-canvas）」（MIT License，面向图片创作的开源工作台）的**本次更新**，制作一支：

- 时长 **90.0 秒**；
- 画幅 **1920×1080（16:9）**；
- 帧率 **30fps**；
- 风格 **L43 活体实机录屏（Living Screencast）**；
- 全中文界面与字幕，**无旁白、无 TTS**，只有音效 + 轻配乐；
- 一镜到底：镜头在同一块屏幕里连续运动，只在章节交界用像素擦除/章节胶囊擦除过渡；

# 四、输出形态（硬性）

1. **只输出一个完整、自包含的 `index.html`**：HTML + CSS + JS 全部内联；不引用任何外部库、CDN、图片、音频文件。
2. 唯一允许的外部资源是仓库内的字体文件（用相对路径 `../../web/public/fonts/CascadiaCode.woff2`、`../../web/public/fonts/FZXiaoBiaoSong.woff2`；必须带 `local()` 与系统字体回退栈，字体缺失也要能正常运行）。
3. 页面打开后：1920×1080 的 `#stage` 等比适配窗口（`transform: scale()` 居中，四周留背景色），不得出现滚动条。
4. 必须暴露：
   - `window.seek(t)`：纯函数渲染；
   - `window.renderAudio()`：导出 90.0s WAV（见 §音频）；
   - 键盘：空格暂停/继续、`R` 回到开头（可选）、`M` 静音切换（可选，但 URL 参数必须有）。
5. URL 参数：`?t=12.5` 定格到指定秒；`?mute=1` 静音；`?debug=1` 显示帧号与单帧耗时（可选）；无参数时从 0 开始循环播放。

# 五、分层与坐标系

严格按以下层级实现（不得增删中间层）：

#viewport(1920×1080) > #camera(transform) > #stage(1920×1080)
    ├─ #wallpaper（暖米色渐变 + 轻微暗角 + 极轻噪点）
    └─ #window（设计尺寸 1366×768；left:191.625px; top:108px; transform:scale(1.125); transform-origin:0 0;
                 border-radius:12px; overflow:hidden; 软阴影）
         ├─ .window-chrome（三枚交通灯圆点 + 居中细体标题「无限画布」）
         ├─ .app（真实 UI 层：顶栏 56px + 各页面）
         └─ #pixelLayer（1366×768 canvas；image-rendering:pixelated；画小方/道具/尘土）
#viewport > #hud（1920×1080 覆盖层，不参与相机变换：章节胶囊/键击 HUD/字幕/时间标签）

坐标系有三套，换算必须集中写常量，不许散落：

- **窗口坐标**：1366×768，`u = 8`；小方 12×12 格 = 96×96。
- **舞台坐标**：`stageX = WIN_LEFT + winX * WIN_SCALE`，`stageY = WIN_TOP + winY * WIN_SCALE`。
- **相机**：`#camera.style.transform = translate(-cx*zoom, -cy*zoom) scale(zoom)`；`cx/cy` 是舞台坐标里的相机中心；`zoom ∈ [1.0, 2.2]`；必须 clamp 到「可见矩形始终在 1920×1080 舞台内」，任何一帧都不许露出舞台之外（墙纸必须铺满可见区域）。

# 六、确定性渲染（最重要的一节）

1. 全片只有一个纯函数入口 `seek(t)`：`t` 单位秒，范围 0.0–90.0。`seek(t)` 内先做 `const f = Math.round(t * 30)`，再用 `t = f / 30` 归一化，保证 30fps 阶梯。
2. `seek(t)` 内**禁止**读取真实时间（`Date.now()`、`performance.now()`、`rAF` 时间戳）、禁止 `Math.random()`、禁止依赖「上一次调用留下的状态」。
3. 随机数只用 `mulberry32(seed)`，种子写死 `const SEED = 0x1F2E3D4C`，且只在启动时消费一次，生成静态参数表（尘土粒子、噪点、眨眼/呼吸相位、道具偏移等）。运行期用表或纯函数 `hash01(i)` 取值。
4. 禁用所有 CSS `animation` / `transition` / `@keyframes` 参与画面；动画一律由 `seek(t)` 计算后写入内联 style 或 canvas。
5. 播放循环：
   （播放循环，缩进示意）
   let t = startT, playing = true;
   function tick(now) { if (playing) { t = (t + dt) % 90; } seek(t); requestAnimationFrame(tick); }
   `dt` 只用于推进播放时间，不参与画面计算。
6. `?t=12.5`：进入页面后立即 `seek(12.5)` 并停止播放（不启动 rAF）；空格可继续。
7. `?mute=1`：AudioContext 不创建或 `masterGain.gain = 0`；`?t=` 定格时默认不启动音频（便于截图）。
8. 所有 DOM 尺寸必须来自真实渲染结果（`offsetWidth`/`offsetHeight`）或 CSS 常量，不许手写「猜的」坐标；小方的落点必须**每帧从 DOM 测量**得出（见 §相机与测量）。

# 七、UI 重绘纪律

1. 所有界面按产品真实结构重绘：顶栏 56px（左侧 Logo + 「无限画布」+ 导航「AI 对话 / 我的画布 / 生图工作台 / 视频创作台 / 提示词库 / 我的资产」，右侧配置入口）；`/chat` 侧栏 276px 底色 `#f2efe8`；`/image` 侧栏 252px；主区底色 `#faf9f5`；深色对应 `#1c1b19` / `#171614`。
2. 文字优先用 HTML 文本渲染（保证锐利），不许把整屏文字画进 canvas。
3. 每个被小方踩过、被相机推近、被字幕提到的元素，都必须带 `data-anchor="<名字>"`（锚点清单见随附规范），并按真实文档流布局。
4. UI 动效只做产品自己会有的：弹层 pop、卡片淡入、步骤展开、消息进入、骨架 shimmer。不许发明产品没有的转场。
5. 状态由「镜头状态对象」驱动：每个镜头声明 `page`、可见元素、文案、节点/消息数组、光标位置、小方状态；`seek(t)` 里按时间轴事件表切换状态，再渲染。
6. **任何用户操作都必须在画面可见**：光标路径、点击、键入；键击必须同步出现在右下角 KeyCastr 风格 HUD 里。

# 八、小方（像素小人）

1. 12×12 像素矩阵（字符串数组或二维 0/1 表），`u = 8` 窗口像素；Canvas2D `imageSmoothingEnabled = false`；位置量化到 `u` 的整数倍。
2. 配色：主体 `#E8703A`、暗部 `#A8451E`、眼睛/嘴 `#241F1B`、高光 `#FFE9DA`。**全片只有小方和它的道具能用这个饱和橙**，产品 UI 里不出现。
3. 站立规则：**重力 = UI 的上边缘**。小方双脚永远等于目标元素的上边缘 `y`；`x` 落在元素的水平范围内并按 `u` 量化；位置每帧从 DOM 测量（`offsetParent` 链累加），不许手写。
4. 动作：待机呼吸（随 72 BPM 节拍轻微挤压）、不规则眨眼、走（两帧交替、按朝向翻转）、跳（蓄力下蹲 → 起跳拉伸 → 收腿 → 落地挤压 + 阻尼回弹 + 尘土）、被光标戳、挥手、抱道具、推、捂眼偷看、睡觉（闭眼 + Z 像素）。
5. 眼睛承担表演：中立/看左/看右/看上/看下/瞪大/开心/闭眼/眨眼，按分镜给的表演切。
6. 小方永远不漂浮、不挡要读的字、不压字幕；同一镜头里不出现第二种饱和色。

# 九、相机

1. 只有一个相机：`#camera` 的 `translate + scale`；关键帧表 `{t, cx, cy, zoom}`，用弹簧缓动（推荐 critically damped spring 或 `1 - Math.pow(1-p, 3)` 的缓出）插值。
2. `zoom ∈ [1.0, 2.2]`；推近（push-in）、静止慢漂（drift）、甩镜（whip-pan）、拉回整窗（pull back）、跟随（follow）、移焦（rack focus）按分镜使用。
3. 甩镜的动态模糊只能加在**未变换的外层包装元素**上（`filter: blur()` + 方向偏移），绝不加在 `#camera` 或 `#stage` 上，否则像素小人会被拉花。
4. 绝不虚化要读的文字；绝不 zoom 到露出舞台之外。
5. 章节交界：先像素擦除/胶囊擦除，再切相机；同幕内相机连续，不许硬切。

# 十、信息层（HUD）

1. 全片只有四样叠加层：左上章节胶囊（`01`–`04`，毛玻璃）、右下 KeyCastr 风格键击 HUD、底部字幕胶囊、右上可选「▶▶ 4×」时间标签。**不许再加第五种装饰层**，不许做片头大标题卡。
2. 字幕：底部居中毛玻璃胶囊，最多 2 行、每行 ≤ 18 个汉字；同一时刻最多 1 条；不得遮挡被讨论的元素、不得压住小方；停留时长 = `max(1.8s, 字数×0.18s + 0.6s)`。
3. 键击 HUD：显示 `⌘K`、`⌘R`、`Enter` 等；每次按键弹出 + 停留约 1.2s，多个键可叠放。
4. 章节胶囊：出现后 2.2s 淡出；数字用 Cascadia Mono，中文用方宋。
5. 「▶▶ 4×」：只在时间压缩段落出现（刷新恢复），带轻微闪烁（由 seek(t) 计算，不用 CSS 动画）。
6. 片尾 end card 是**片尾专用的收束元素**（「开源 · 免费 · MIT」+ 仓库名 + `{{版本号}} · 本次更新（开发中）」），不属于正片四层信息层，只在 86.4s 后出现。

# 十一、音频（WebAudio 全合成）

1. 两层配乐：hi-fi 层（立式钢琴、低音提琴拨弦、刷鼓、钟琴）+ chiptune 层（方波/脉冲，只代表小方）。72 BPM，一层一层进入，按分镜的情绪曲线。
2. Foley：键盘 thock + click（带人类节奏抖动）、触控板点击、面板 swish、弹层 pop、通知 chime、刷新 whoosh、快门；小方的脚步/起跳/落地/尘土/睡觉 Z 是 8-bit。
3. 不出现旁白、TTS、罐头史诗配乐、女声吟唱；不使用任何外部音频文件。
4. 混音目标 −14 LUFS；关键承诺前 0.6s 静音到房间底噪；深色主题切换期间整条总线低通（约 800Hz），切回时恢复。
5. 两套输出必须共用同一份「事件表」：
   - 在线：`AudioContext` + 合成节点，跟随播放时刻调度；
   - 离线：`window.renderAudio()` 用 `OfflineAudioContext(2, 48000*90, 48000)` 渲染 90.0s，编码 16-bit PCM 立体声 WAV 并触发下载（文件名 `l43_audio_90s.wav`）。
   - 两套方案的音符、时间、参数必须逐一致（同一事件表），导出长度必须精确 90.000s。

# 十二、性能预算与降级

1. 目标：1080p 30fps 稳定；单帧 `seek(t)` 的 JS 执行 ≤ 8ms（不含浏览器绘制）。
2. 减少 DOM 写入：同一帧内先读后写；只更新有变化的节点（用缓存的上一帧值比对）。
3. 大列表/12 个节点用 `transform` 位移，不改布局属性（`left/top/width/height`）。
4. 测量缓存：同一镜头状态内，锚点矩形只测一次并缓存；状态切换（`stateKey` 变化）才失效重测。移动中的光标/小方目标每帧测量。
5. 降级策略（按顺序启用，不得改变画面构图）：
   - 第一级：尘土粒子 24 → 12 → 6；
   - 第二级：关闭墙纸噪点层与窗口阴影的模糊（换成低清阴影）；
   - 第三级：毛玻璃 `backdrop-filter` 换成半透明纯色；
   - 第四级：像素层画布渲染改为「每 2 帧重绘一次静态道具，小方仍逐帧重绘」。
   降级只允许影响质感细节，不允许影响可读文字、构图、时间轴与字幕。
6. `?debug=1` 时在右上角显示 `f / 2700`、`seek ms`，便于定位性能问题。

# 十四、风格基准：L43 英文风格提示词（逐字原文，不得改写）

# Living Screencast — Style Prompt

> A product walkthrough that looks like a real screen recording, where a low-resolution mascot lives inside a high-resolution interface and acts out what the software is doing.
>
> Never copy any referenced characters, UI, music or footage.

A walkthrough of a piece of software, typically 45–75 s. The user gives the product and the features; you decide the story, shots, choreography, sound and music.

## 1. Essence, and what it is not

The film looks like a **screen recording of the real product**, but it is not a recording. Every window, menu, diff line and button is **redrawn in 2D (HTML/CSS/SVG)**, so the camera can go anywhere, every pixel is controllable and text stays sharp at any zoom.

A **mascot made of big square pixels** lives in that high-resolution world. The clash of two resolutions, a hard-edged low-res sprite against anti-aliased UI, is the look.

The mascot is the software's agency made visible: when the software reads, it runs along the rows it reads; when it plans, it holds a pixel pencil; when it tests, it stomps the button.

**Two actors, never a hand:** the **cursor** is the user; the **mascot** is the software.

Not a dark tech keynote (no black stage, no invented abstract UI: this is the real product), not a pixel-art game (the world is hi-res vector UI; only the mascot and its props are pixels), not a real capture (nothing is a screenshot).

## 2. Materials & rendering

- **Real UI, redrawn**: every label, mode name and shortcut matches the real product; no screenshots, no lorem ipsum. Demo content (code, data, test output) is coherent, and the app under test really changes.
- **Pixel grid is sacred**: the mascot, its props (pencil, "!", sparkles, heart, dust) and trails share one square-pixel grid with crisp edges. It scales with the camera; its position snaps to half-pixels, so its motion feels stepped.
- **Gravity = top edges of UI**: the mascot only stands on the top edge of a real element (input box, menu, list row, code line, button, status bar, the letters of a heading). Its position comes from **measuring the live DOM** every frame, never hand-placed coordinates.
- **Window on wallpaper**: the app floats on a desktop with a soft shadow; zoom never shows beyond the monitor.
- **Depth** only where it serves attention: rack focus (blur the pane that doesn't matter), a vignette spotlight. Never blur text the viewer must read.
- **Motion blur** is derived from camera speed and applied as an anisotropic blur on an **untransformed wrapper**, only on whips. Slow moves stay sharp.

## 3. Colour logic

- The product's own interface colours rule: follow its real light and dark themes exactly.
- The mascot keeps the product's or brand's mascot colour, or one saturated hue that no UI element uses, so it finds the eye in any frame.
- Overlays (chapter pill, key HUD, captions) are neutral frosted glass; one accent at most, taken from the product.
- A theme switch can be a story event: the whole film may change state with it.

## 4. Type & subtitles

- UI type follows the product (or licence-free look-alikes such as Inter, JetBrains Mono, a serif for editorial UIs).
- **Information layers only**: a chapter pill (01–04), a KeyCastr-style keystroke HUD, frosted-glass caption pills, an optional "▶▶ 4×" time-lapse tag. Nothing else overlays the screen.
- Captions sit in a pill at the bottom, never over the element being discussed and never under the mascot; hold ≥ max(1.8 s, speech + 0.6 s).
- A title, if any, is diegetic: it appears as part of the UI (an empty-state heading, a window title, a notification).

## 5. Motion quality

- 30 fps; UI on ones; mascot position stepped to its pixel grid.
- **Mascot acting**: jumps with anticipation crouch, stretch on take-off, tucked legs, landing squash with a damped bounce and dust. Idle breathes (a tiny squash) on the score's beat and blinks irregularly. Walks by leg alternation, flipping the sprite for direction.
- **Eyes carry the acting** (neutral / left / right / up / down / wide / happy / shut / blink): they look at what matters. Arms: down / up (cheer) / wave.
- **Cursor**: smoothed, spring-eased paths, small push on click, never teleports.
- **Cause and effect**: every mascot action triggers a real UI state change; every user action is a cursor move, click or keystroke shown on the HUD.
- UI animates like the real product (its own menus, popovers, diff reveals); don't invent flourishes the product doesn't have.

## 6. Camera grammar

A recording-software camera: one continuous take inside the screen, zoom ≥ 1, cuts only under chapter transitions. Opening and ending come from the topic.

| Move | What it expresses | Can serve |
|---|---|---|
| Push-in to the cursor or caret | "this is where it happens" | typing a prompt; choosing a menu item; a setting |
| Slow drift at rest | the app is alive while we listen | a line of narration; waiting for a result |
| Whip-pan between panes (with blur) | cause here, effect there | sending a message → a result appearing; code → preview |
| Push-in + vignette freeze | the one promise to remember | a safety guarantee; a price; an undo |
| Rack focus between panes | attention moves, nothing else does | reading files; logs scrolling while chat waits |
| Pull back to the full window | the whole workflow in view | a summary; parallel tasks; before/after |
| Follow the mascot along a list | the software working through items | scanning results; a checklist; a migration |
| Split-window reframe | two things at once | parallel sessions; compare two versions |

Framing: the thing being discussed and its caption never overlap; the mascot never covers text to be read. Transitions: chapter pill wipes, pixel wipes, a theme reveal circle; never dissolves or screenshots.

## 7. Sound palette

- **Two resolutions in the music**: a hi-fi layer (piano, upright or electric bass, brushed or tight kit, glockenspiel, real samples) is the world; a chiptune square or pulse voice is the mascot. They can trade, duet or merge.
- Options: a low-passed "night" version of the band for a dark theme; a tom fill and crash at chapter seams; dropping the drums to build tension; the mascot's notes on words it lands on; a stereo split for split screens; a single held pad under a freeze.
- **Foley**: keyboard (a thock plus a click, human timing jitter), trackpad clicks, pane swishes, popup pops, notification chimes, CI ticks, a shutter for screenshots. Mascot steps, jumps and landings are 8-bit.
- **Silence**: a short drop to room tone before the key promise makes it land.
- **Voice**: calm, one feature per line; product names verified with whisper. Keep effects off word onsets. Duck music under voice; −14 LUFS.

## 8. Native moves

A menu: use the ones your walkthrough needs.

- **Match-cut origin.** The mascot is born from something already in the UI (a logo's block characters, an icon, a loading spinner) and climbs out, leaving an outline. *Fits content like:* a chat bubble turning into a guide; an icon becoming an assistant; a spinner becoming a helper.
- **Diegetic title.** The name appears as a real UI element; the mascot lands on it on a downbeat. *Fits content like:* an empty state; a new-project dialog; a welcome email.
- **Moving floor.** The mascot rides a caret, a popup, a sent message, a progress bar. *Fits content like:* a message flying into a thread; an upload bar; a drag-and-drop.
- **Time-lapse with a tag.** Long work runs at N× with a flashing tag and rack focus. *Fits content like:* indexing a library; a data import; a build.
- **Spotlight freeze.** Push in and vignette the one badge that holds the promise. *Fits content like:* "Saved"; "Encrypted"; "No charges until…".
- **The film changes state.** A toggle's effect escapes the preview and takes over the whole film, and returns later. *Fits content like:* dark mode; a language switch; offline mode.
- **Cell division.** A new session or window splits the screen and the mascot splits with a pixel burst. *Fits content like:* parallel tasks; multiple accounts; team members.
- **Cursor and mascot as characters.** The cursor pets, pokes or drags the mascot, and it reacts. *Fits content like:* approving a suggestion; undoing; onboarding delight.
- **Karaoke-ball words.** The mascot hops from word to word as they are spoken. *Fits content like:* a slogan; a shortcut list; step names.

## 9. Pitfalls of the medium

- Invented features or renamed modes → check every button, mode and shortcut against the product's documentation; if it isn't in the docs, it isn't in the film.
- The mascot floats or drifts off its element → measure the DOM every frame, stand only on top edges.
- The mascot covers text or sits under a caption → reserve a text-free lane for it.
- Blur-filter "fake depth" on text you want read, or zooming out past the screen → rack focus only on panes not being read; zoom ≥ 1.
- A hand, arm or finger on screen → the cursor is the user.
- Motion blur applied to a transformed layer smears the pixel sprite wrong → blur an untransformed wrapper, and only on whips.
- A keypress or pop landing on a product name masks it → shift foley off word onsets; re-check with whisper on the final mix.
- TTS mispronounces the product name → try voices and spellings, verify with whisper.

# 十五、本项目适配规则（简报 §2.2 十七条，逐字，强制执行）

1. **两层分辨率是本体**：真实产品 UI 用 HTML/CSS/SVG **重绘**（零截图、零录屏贴图），高分辨率、文字锐利；像素层只属于小方、它的道具、轨迹和尘土。两种分辨率的硬边冲突就是本片的「look」。
2. **窗口浮在墙纸上**：暖米色渐变墙纸 + 轻微暗角；应用窗口圆角 12px、软阴影；相机 zoom ≥ 1，任何镜头都不出现窗口外的「屏幕之外」。
3. **UI 尺寸基准**：窗口设计尺寸 **1366×768 CSS px**（16:9 精确）；在 1920×1080 画布内等比缩放并居中，默认全窗可见（约 1536×864 屏幕像素）。相机推近范围 1.0×–2.2×。
4. **重力 = UI 的上边缘**：小方只站在真实元素的上边缘（顶栏底边上方、欢迎标题顶边、输入框顶边、消息气泡顶边、工具卡顶边、结果卡顶边、队列胶囊顶边、画布节点顶边、按钮顶边、成品海报顶边、窗口标题栏顶边）。位置**每帧由 DOM 测量**（`offsetParent` 链累加，不受相机 transform 影响），不许手写坐标。
5. **像素网格神圣**：小方与道具共用一套正方形像素格，基础像素单位 `u = 8 CSS px`（窗口内）；落位坐标量化到 `u`，运动按 30fps 阶梯；`image-rendering: pixelated`，禁止抗锯齿、禁止半像素。
6. **两个演员，永远没有手**：光标 = 用户（平滑弹簧路径、点击有推动感、从不瞬移）；小方 = 软件（读、想、做、等、救的化身）。任何用户操作必须在画面里可见（光标路径 / 点击 / 键击 HUD）。
7. **因果必须闭合**：小方每个动作都要触发真实 UI 状态变化（跳上输入框 → 聚焦；按住发送 → 消息发出；推节点 → 网格排布；扑向失败卡 → 重试成功）。UI 动效只用产品自己会有的（弹层 pop、卡片淡入、步骤展开），不发明产品没有的花哨转场。
8. **颜色纪律**：UI 只用产品真实浅/深主题色（`#faf9f5` / `#f2efe8` / stone 系 / `#171717` 主按钮）；**小方独占饱和橙 `#E8703A`**（产品 UI 中不出现该色）；叠加层只用中性毛玻璃 + 至多一个产品已有强调色。**深色主题切换是剧情事件**：第 4 幕切换时全片短暂变暗、音乐低通、再切回。
9. **字体**：UI 用产品字体（Cascadia Mono 英数 + 方正小标宋中文，@font-face 指向仓库 `web/public/fonts/`，附回退栈）；标题与正文全部按真实产品字号（11/12/13/14/16/18px，欢迎标题 28px 级）。
10. **信息层只有四样**：左上章节胶囊（01–04，毛玻璃）、右下 KeyCastr 风格键击 HUD、底部字幕胶囊、右上可选「▶▶ 4×」时间标签。**除这四样和窗口 chrome 外，不叠加任何装饰层**；不做片头大标题卡（片名用 diegetic 方式出现在 `/chat` 欢迎标题上）。
```

### 4.7 演示内容（生成的图片 / 海报）怎么画

**禁止用真实图片**。所有「生成结果」都是 CSS/SVG 画出来的抽象海报，规则如下：

1. 每张海报 = 底色渐变 + 2–4 个几何色块 + 1 个主体剪影（咖啡杯 / 山 / 圆日 / 花瓶，用 SVG path 画），**不写任何文字**（避免发明文案）。

### 5.1 基础参数

### 5.2 基础站立姿势矩阵（`idle`）

```text
............
............
..HHBBBBBB..
.BBBBBBBBBB.
ABBKKBBKKBBA
ABBKKBBKKBBA
ABBBBBBBBBBA
.BBBBKKBBBB.
.BBBBBBBBBB.
..DDDDDDDD..
..BBB..BBB..
..DDD..DDD..
```

- 第 0–1 行留空：给跳跃拉伸/道具/睡觉 Z 留头room，**永远不要把有用像素画进这两行**（否则落地挤压没有余量）。

- 手臂在 x=0 与 x=11，y=4..6（下垂姿势）；换姿势时只改这两列与头顶/腿。

### 5.6 动作时序（30fps 帧表，与 02 §3.3 一致）

| 动作 | 帧数 | 关键帧 |
|---|---|---|
| 起跳（不含空中） | **8 帧**（0.267s） | 预备下蹲 **3 帧** → 起跳拉伸 **3 帧** → 收腿 **2 帧**；之后进入空中段 |
| 空中 | **30–50 帧**（1.0–1.67s） | 按抛物线移动（x 由动作逻辑给、y 量化到 u）；顶点在 40%–50% 处 |
| 落地 | **6 帧**（0.2s） | 挤压 **2 帧** → 阻尼回弹 **4 帧**；同时喷尘土 **3–4 粒**（最多 12 粒） |
| 走 | **2 帧**循环 | `walkA`/`walkB` 交替、按朝向翻转；步频 6 帧/步（5 步/秒） |
| 眨眼 | **3 帧** | 睁 → `blink` → 睁；间隔 **1.4–3.2s** 不等（由启动时 `mulberry32` 相位表决定，禁止 `Math.random`） |

| 捂眼偷看 | 16 帧 | 捂眼 6 → 闭眼 3 → 睁眼偷看右 3 → 放下 4 |
| 睡觉 | 循环 90 帧 | `sleep` 姿势＋呼吸 1 行起伏＋Z 像素 2×2 上浮 0.6s 循环 |
| 推 | 6 帧 | 前倾 2 → 前推 2 → 回正 2 |

### 5.8 落位量化算法（照抄即可）

```js
const U = 8, SPRITE_W = 12 * U, SPRITE_H = 12 * U;

// 测量：offsetParent 链累加（不受 #window 的 transform 影响）
function measure(anchorName) {
  const el = document.querySelector(`[data-anchor="${anchorName}"]`);
  if (!el) return null;
  let x = 0, y = 0, node = el, app = document.getElementById('app');
  while (node && node !== app) {
    x += node.offsetLeft; y += node.offsetTop;
    node = node.offsetParent;
  }
  return { x, y: y + 36 /* chrome */, w: el.offsetWidth, h: el.offsetHeight };
}

// 站立：脚 = 锚点上边缘；x 量化到 u 且夹在锚点水平范围内
function standOn(anchorName, fx = 0.5, minMargin = 0) {
  const r = measure(anchorName);
  if (!r) return null;
  const rawX = r.x + r.w * fx - SPRITE_W / 2;
  const lo = r.x + minMargin;
  const hi = r.x + r.w - SPRITE_W - minMargin;
  const x = Math.round(Math.min(Math.max(rawX, lo), Math.max(lo, hi)) / U) * U;
  return { x, y: r.y - SPRITE_H, anchor: anchorName };
}

// 非站立（空中/从边沿坠落）：y 由动作曲线给，x 仍量化
function airAt(anchorName, fx, offsetY) {
  const p = standOn(anchorName, fx);
  return p ? { x: p.x, y: Math.round((p.y + offsetY) / U) * U } : null;
}
```

> **禁止**：手写小方坐标；用 `getBoundingClientRect` 直接当落点（会被相机 `scale` 污染，除非除以当前 zoom 并换算，不推荐）；把锚点加在 `position:fixed` 元素上（会脱离文档流）。

## §6 相机与 DOM 测量规范

### 6.1 相机模型（坐标口径以 02 §1.3 为准）

- 只有一个相机：`#camera`，作用于 `#stage`（1920×1080）。相机状态记作 `{ zoom, cx, cy }`，其中 **`(cx, cy)` 是窗口设计坐标（1366×768，左上原点）里的取景中心**，`zoom ∈ [1.00, 2.20]`。
- 窗口坐标 → 舞台坐标的换算（常量见 §1.2）：
  ```js
  const toStage = (x, y) => ({ sx: WIN_LEFT + x * WIN_SCALE, sy: WIN_TOP + y * WIN_SCALE });
  ```
- 变换公式（把 `(cx,cy)` 换算成舞台点 `(sx,sy)` 后居中）：
  ```js
  const { sx, sy } = toStage(cx, cy);
  camera.style.transformOrigin = '0 0';
  camera.style.transform = `translate(${-sx * zoom + 960}px, ${-sy * zoom + 540}px) scale(${zoom})`;
  ```
- **可见矩形**（舞台坐标）：`[sx - 960/zoom, sx + 960/zoom] × [sy - 540/zoom, sy + 540/zoom]`。
- **clamp（必须）**：任何一帧可见矩形都不得越出 1920×1080 舞台。
  ```js
  zoom = Math.min(Math.max(zoom, 1.00), 2.20);
  const halfW = 960 / zoom, halfH = 540 / zoom;
  sx = Math.min(Math.max(sx, halfW), 1920 - halfW);
  sy = Math.min(Math.max(sy, halfH), 1080 - halfH);
  ```
  `zoom = 1.00` 时上式强制 `(sx,sy)=(960,540)`，即整窗完整可见（窗口 1536.75×864 居中、四周墙纸 ≥191px），与 02「拉回整窗 = zoom 1.00」一致。
- 关键帧表：`CAM = [{ t, cx, cy, zoom, ease }, ...]`，02 每镜的「起 zoom/焦点 → 止 zoom/焦点」直接转成相邻关键帧；**同幕内相邻镜头的起点必须等于上一镜终点**（数值连续）。
- 缓动：默认 `cubic-bezier(.22,1,.36,1)`（02 §1.3），用确定性的 cubic-bezier 求解函数实现：
  ```js
  function cubicBezier(x1, y1, x2, y2) {
    return (x) => {                       // 输入线性进度 0..1，输出缓动值
      if (x <= 0) return 0; if (x >= 1) return 1;
      let lo = 0, hi = 1, mid, t0, t1;
      for (let i = 0; i < 24; i++) {
        mid = (lo + hi) / 2;
        t0 = 3 * (1 - mid) ** 2 * mid * x1 + 3 * (1 - mid) * mid ** 2 * x2 + mid ** 3;
        if (t0 < x) lo = mid; else hi = mid;
      }
      const u = (lo + hi) / 2;
      return 3 * (1 - u) ** 2 * u * y1 + 3 * (1 - u) * u ** 2 * y2 + u ** 3;
    };
  }
  const EASE = cubicBezier(0.22, 1, 0.36, 1);
  ```
  甩镜可另用 `cubic-bezier(.33,1,.68,1)`（02 逐镜字段里直接给了曲线的以逐镜为准）；过冲上限 ≤4%，超了就是参数写错。
- 时长建议（02 §1.3）：甩镜 0.35–0.55s；推近 0.7–1.2s；慢漂 2–4s 内变 8–15% zoom；「整窗拉回」用 0.9s 左右。
- 产品内的画布视口（缩放/平移）是**产品交互**，与电影相机叠加：计算小方落点时，先应用产品视口变换，再测 DOM 的最终屏幕矩形（见 §6.4）。

### 6.2 动态模糊（只给甩镜）

- 结构：`#viewport > #motionWrap > #camera > #stage`；模糊只加在 **`#motionWrap`**（未变换层）。
- 由相机速度 `v = |Δcx| + |Δcy|` 估算：`blurPx = clamp(v / 90, 0, 14)`；同时给 `#motionWrap` 加 `transform: translateX(${dir * blurPx * 0.6}px)` 造方向性拖影。
- 甩镜结束帧必须 `blur → 0`；**推近/拉回/慢漂不加模糊**（慢动作保持锐利）。
- 文字可读性优先：模糊期间不得让被读文字成为画面主体（02 的甩镜都发生在页间切换）。

### 6.3 rack focus（移焦）

- 只对「不读的窗格」加 `filter: blur(6px)`，例如甩镜时的一侧面板；**被讨论的文字永远不虚化**。
- 实现为 2 个离散档位（0 / 6px），用 6 帧淡入淡出（`opacity` 或 CSS `filter` 值按 `seek(t)` 插值）。

### 6.4 DOM 测量规则

1. 锚点元素必须带 `data-anchor`，且其 `offsetParent` 链能一路走到 `#app`（`#app` 为 `position:relative`）。
2. 测量函数见 §5.8；**每帧只测当前用到的锚点**（通常 1–3 个），其余用缓存。
3. 缓存键 = 当前镜头 `stateKey`；`stateKey` 变化（页面/消息/节点数量/主题切换）时全部失效并重测。
4. 禁止用 `getBoundingClientRect()` 作落点（受相机 `scale` 与 `translate` 污染）；若必须用，先除以 `#camera` 当前 `zoom` 并减去 `translate` 偏移，且写明换算。
5. 主题切换/字体加载完成后必须强制重测一次（`document.fonts.ready.then(() => invalidate())`），否则字宽变化会让锚点漂移。
6. 测量只读 DOM，不写 DOM；同一帧内先测后画，避免强制同步布局（layout thrash）。

### 6.5 相机与 HUD 的关系

- HUD（章节胶囊/键击/字幕/时间标签）**不参与相机变换**，固定在 1920×1080 视口上；相机推近时 HUD 字号不变。
- 字幕与画面的避让：字幕胶囊占据底部约 150px 高；相机的 `cy` 在需要时可上移，保证被讨论元素不被字幕压住（02 的相机参数已考虑，实现时以「不遮挡」为最终判据）。


## §7 时间轴与 HUD 规范

### 7.1 时间轴数据模型

整部片子只有一份「事件表」，由 02 的逐镜表 1:1 转录。**03 不新增事件、不删事件、不改时间码。**

```js
const FPS = 30, TOTAL = 90.0;
const FRAMES = TOTAL * FPS;                       // 2700

// 镜头表：从 02 逐镜表逐字转录（镜号/起/止/章节/状态）
const SHOTS = [
  { id: 'S01', t0: 0.0,  t1: 0.0,  chapter: null, state: 'cold-open-wallpaper' },
  // …
];

// 事件表：类型固定为下面 7 种，字段按类型取
const EVENTS = [
  { t: 0.0, type: 'state',  state: 'cold-open-wallpaper' },
  { t: 0.0, type: 'camera', cx: 960, cy: 540, zoom: 1.0, ease: 'linear' },
  { t: 8.0, type: 'chapter', index: '01', label: '它会自己接活' },     // 出现 2.2s 后淡出
  { t: 8.0, type: 'sfx',    name: 'tomFill', gain: 0.5 },
  { t: 12.3, type: 'key',   keys: ['⌘', 'K'] },
  { t: 15.0, type: 'caption', text: '…', hold: 2.4 },                  // 与 02 字幕清单逐字一致
  { t: 50.2, type: 'theme',  to: 'dark', dur: 0.4 },
  { t: 55.0, type: 'timelapse', on: true },
  // …
];
```

**`seek(t)` 的执行顺序**（必须照此顺序，保证可定格）：

1. `t = clamp(t, 0, TOTAL)`；`f = Math.round(t * FPS)`；`tf = f / FPS`。
2. 找 `SHOTS` 里 `t0 <= tf < t1` 的镜头（最后一帧边界归片尾）；应用它的 `state`。
3. 按时间顺序应用 `tf` 之前的所有 `state` / `theme` / `chapter` / `timelapse` 事件，得到当前「世界状态」。
4. 相机：取 `tf` 前最近一个 camera 关键帧到下一个关键帧之间插值（§6.1）。
5. 小方：按 02 该镜的锚点/姿势/动作时序计算（§5.6）。
6. 光标：按 02 该镜的路径、点击、键入时刻计算（弹簧路径 + 点击压缩）。
7. HUD：字幕/键击/章节/时间标签按当前时刻计算可见性与位置（§7.2–§7.5）。
8. 音频：只有「播放中且非静音」时，调度 `[tf, tf + 0.2)` 内尚未调度的音效事件；定格与 `?mute=1` 不调度。
9. 渲染：只写有变化的 DOM/canvas。

**时间一致性硬约束**：`SHOTS[n].t1 === SHOTS[n+1].t0`（允许相等，不允许空隙）；`SHOTS[0].t0 === 0.0`；`SHOTS[last].t1 === 90.0`。三者任一不成立，页面打开时在控制台报错并在 `?debug=1` 角标显示红色。

## §8 WebAudio 音频规范与 Cue Sheet

### 8.1 总原则

| 项 | 规范 |
|---|---|
| 合成方式 | **WebAudio 纯合成**，零外部音频文件；所有声音由振荡器、噪声缓冲、滤波器、包络在运行时生成 |
| 采样率 | 在线 `AudioContext` 用浏览器默认（通常 48kHz）；离线 `OfflineAudioContext` 固定 **48000Hz**，保证 WAV 可复现 |
| 声道 | 立体声（离线 2 声道；在线 `StereoPannerNode` 铺开） |
| 总时长 | 90.000s（4,320,000 采样 @48kHz） |
| 配乐 | **72 BPM**：1 拍 = 0.833333s，1 小节（4/4）= 3.333333s，90s = **27 小节整**（时间轴与音乐骨架天然对齐） |
| 两层 | hi-fi 层 = 世界（立式钢琴 / 低音提琴 / 刷鼓 / 钟琴 / pad）；chiptune 层 = 小方（方波/脉冲） |
| 无旁白 | 不生成任何语音、不用 TTS、不用外部人声采样 |
| 混音目标 | **−14 LUFS**（离线渲染后可用 ffmpeg `loudnorm` 复核，见 §11） |
| 静音参数 | `?mute=1` 时物理不启动 AudioContext（不是 gain=0，便于截图环境零音频） |

### 8.2 音乐结构（72 BPM，两层；与 02 §7.1 一致）

> 72 BPM：1 拍 = 0.833s，1 小节（4/4）= 3.333s，90s = 27 小节整。下表与 02 §7.1「音乐情绪曲线」逐段一致，03 不得自创段落。

| 时间 | 段落 | hi-fi 层 | chiptune 层 | 情绪/处理 |
|---|---|---|---|---|
| 0.0–8.0 | 冷开场 | 房间底噪＋钟琴单音（1.0 C5、5.4 G5） | 无 | 安静、悬念 |
| 8.0–14.0 | 第 1 幕前段 | 立式钢琴分解和弦进入（C 大调） | 小方步声/起跳 | 轻快 |
| 14.0–28.0 | 第 1 幕后段 | 钢琴＋刷鼓；25.0 收束句 | 键击/跺脚对位 | 轻快收束 |

| 40.0–48.0 | 第 2 幕后段 | bass 走句＋刷鼓 swing；45.6 上扬过门 | 12 连拍/跟随跳 | 推向高潮 |
| 48.0–53.2 | 第 3 幕前段 | 鼓更紧＋bass 心跳感；排队低 pulse | 敲脚、进度 tick | 紧张 |

### 8.5 两套输出方案（必须同时实现）

**方案 A：HTML 内 WebAudio 实时合成（播放用）**

```js
let audioCtx = null, master = null, lp = null, scheduled = new Set();
function ensureAudio() {
  if (audioCtx || MUTE) return;
  audioCtx = new (window.AudioContext || window.webkitAudioContext)();
  master = audioCtx.createGain(); master.gain.value = 0.9;
  lp = audioCtx.createBiquadFilter(); lp.type = 'lowpass'; lp.frequency.value = 18000;
  master.connect(lp).connect(audioCtx.destination);
}
// 每帧调用：只调度 [tf, tf+0.2) 内、未调度过的事件（事件 id 用 `${type}:${t}`）
function scheduleAudio(tf) {
  if (!audioCtx || MUTE || !playing) return;
  for (const ev of sortedAudioEvents) {
    if (ev.t < tf || ev.t >= tf + 0.2) continue;
    const id = `${ev.type}:${ev.t}`;
    if (scheduled.has(id)) continue;
    scheduled.add(id);
    playEvent(ev, audioCtx.currentTime + (ev.t - tf));  // 以当前播放时刻为锚
  }
}
// 暂停：audioCtx.suspend()；继续：resume() 并清空 0.2s 内未播事件
// seek/循环回 0：scheduled.clear() 并 stop 所有已排程节点（维护 activeNodes 列表）
```

- 暂停时 `suspend()`，继续时 `resume()`；定格（`?t=`）**不创建** AudioContext。
- 播放循环回到 0 时，必须 `scheduled.clear()` + 停掉所有 `activeNodes`，否则第二遍会重音。

**方案 B：`renderAudio()` 离线渲染，导出 90s WAV（混流用）**

```js
async function renderAudio() {
  const SR = 48000, LEN = Math.round(SR * 90.0);          // 4,320,000
  const ctx = new OfflineAudioContext(2, LEN, SR);
  const bus = ctx.createGain(); bus.gain.value = 0.9;
  const low = ctx.createBiquadFilter(); low.type = 'lowpass'; low.frequency.value = 18000;
  bus.connect(low).connect(ctx.destination);
  // 与在线完全同一份事件表与合成函数（playEvent 接收任意 BaseAudioContext）
  for (const ev of sortedAudioEvents) playEvent(ev, ev.t, ctx, bus);
  const buffer = await ctx.startRendering();
  const wav = encodeWav16(buffer);                        // RIFF/WAVE, PCM 16-bit, 2ch, 48kHz
  download(wav, 'l43_audio_90s.wav');
}
window.renderAudio = renderAudio;   // 控制台执行；或 ?render-audio=1 自动触发
```

- WAV 编码：标准 44 字节 RIFF 头 + 交错小端 16-bit PCM；导出长度必须 **精确 90.000s**（4,320,000 帧 × 2ch）。
- 校验：`ffprobe l43_audio_90s.wav` 时长应为 90.000000。

## §11 渲染与合成流程

### 11.1 总流程

```text
① 本地静态服务器打开 index.html（浏览器逐段验收 ?t= 定格）
② 控制台 renderAudio() → 下载 l43_audio_90s.wav
③ Playwright 打开同一页面 → 循环 seek(t) + 截图 2700 帧（或管道直送 ffmpeg）
④ ffmpeg 合成无声画面 mp4（H.264 / yuv420p / 30fps / 90s）
⑤ ffmpeg 混流 WAV → 成片 mp4；loudnorm 复核 −14 LUFS
⑥ ffprobe / 抽帧 / 音画同步抽检 → 交付
```

> 备选兜底（只有在 ③ 不可用时）：OBS / QuickTime 屏幕录制。它**不是确定性渲染**，可能出现掉帧、光标、通知弹窗，只能作为最后手段，且必须在报告里注明使用了兜底路径。

### 11.2 页面必须提供的导出钩子

在 `index.html` 里暴露（缺一不可）：

```js
window.seek = seek;                       // 纯函数渲染
window.renderAudio = renderAudio;         // 离线渲染 90s WAV
window.__ready = false;                   // 第一帧可截图时置 true
document.fonts.ready.then(() => { invalidateMeasure(); seek(0); window.__ready = true; });
window.__frameInfo = () => ({ t: currentT, frame: Math.round(currentT * 30) });
```

- `__ready` 必须在「字体加载完成 + 首次 `seek` 完成 + 下一帧 rAF」之后才置 true。
- `?t=` 定格模式不启动播放循环、不创建 AudioContext。

### 11.3 逐帧截图脚本（Playwright，推荐）

`render.mjs`（放在仓库外或 `promo/L43_活体实机录屏/` 下，**不提交**）：

```js
import { chromium } from 'playwright';
import fs from 'node:fs';
import path from 'node:path';

const FPS = 30, TOTAL = 90.0, FRAMES = Math.round(FPS * TOTAL);   // 2700
const URL = 'http://127.0.0.1:8000/promo/L43_活体实机录屏/index.html';
const OUT = path.resolve('frames');
fs.mkdirSync(OUT, { recursive: true });

const browser = await chromium.launch({
  args: ['--force-device-scale-factor=1', '--force-color-profile=srgb', '--disable-lcd-text'],
});
const page = await browser.newPage({ viewport: { width: 1920, height: 1080 }, deviceScaleFactor: 1 });
await page.goto(URL + '?t=0&mute=1', { waitUntil: 'load' });
await page.waitForFunction('window.__ready === true', null, { timeout: 60000 });

for (let f = 0; f < FRAMES; f++) {
  const t = f / FPS;
  await page.evaluate((tt) => window.seek(tt), t);
  // 等两帧，确保 DOM 写入落地
  await page.evaluate(() => new Promise((r) => requestAnimationFrame(() => requestAnimationFrame(r))));
  await page.screenshot({
    path: path.join(OUT, `f_${String(f).padStart(5, '0')}.png`),
    clip: { x: 0, y: 0, width: 1920, height: 1080 },
    animations: 'disabled',
    caret: 'hide',
  });
  if (f % 300 === 0) console.log(`frame ${f}/${FRAMES}`);
}
await browser.close();
```

**更快方案（不落盘 2700 张 PNG）**：把 `page.screenshot()` 的 Buffer 直接写进 ffmpeg 的 stdin：

```js
import { spawn } from 'node:child_process';
const ff = spawn('ffmpeg', [
  '-y', '-f', 'image2pipe', '-framerate', '30', '-i', '-',
  '-c:v', 'libx264', '-preset', 'slow', '-crf', '16',
  '-pix_fmt', 'yuv420p', '-movflags', '+faststart',
  'video_only.mp4',
], { stdio: ['pipe', 'inherit', 'inherit'] });

for (let f = 0; f < FRAMES; f++) {
  await page.evaluate((tt) => window.seek(tt), f / FPS);
  await page.evaluate(() => new Promise((r) => requestAnimationFrame(() => requestAnimationFrame(r))));
  const buf = await page.screenshot({ type: 'png', clip: { x: 0, y: 0, width: 1920, height: 1080 }, animations: 'disabled', caret: 'hide' });
  if (!ff.stdin.write(buf)) await new Promise((r) => ff.stdin.once('drain', r));
}
ff.stdin.end();
await new Promise((r) => ff.on('close', r));
```

**断点续渲**：`if (fs.existsSync(framePath)) continue;`，并用 `f_start` 环境变量从指定帧开始。

### 11.4 导出音频（Playwright 触发下载）

```js
const dlPromise = page.waitForEvent('download');
await page.evaluate(() => window.renderAudio());
const dl = await dlPromise;
await dl.saveAs('l43_audio_90s.wav');
```

如页面在 `file://` 或权限受限环境，改用 `page.evaluate(() => window.renderAudioBase64())` 返回 base64，再在 Node 侧 `Buffer.from(b64,'base64')` 写文件。

### 11.5 ffmpeg 合成命令（逐条可复制）

```bash
# 0) 若用 image2pipe 方案，video_only.mp4 已生成；若用 PNG 序列方案：
ffmpeg -y -framerate 30 -i frames/f_%05d.png \
  -c:v libx264 -profile:v high -level 4.1 -preset slow -crf 16 \
  -pix_fmt yuv420p -g 60 -bf 2 \
  -color_primaries bt709 -color_trc bt709 -colorspace bt709 \
  -movflags +faststart video_only.mp4

# 1) 混流（音频已是 90.000s；-shortest 防尾部溢出）
ffmpeg -y -i video_only.mp4 -i l43_audio_90s.wav \
  -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 \
  -movflags +faststart -shortest l43_promo_1080p30.mp4

# 2) 响度复核（两遍 loudnorm，目标是 −14 LUFS / TP −1.5）
ffmpeg -i l43_audio_90s.wav -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -
# 用输出的 measured_I / measured_TP / measured_LRA / measured_thresh 做第二遍：
ffmpeg -i l43_audio_90s.wav -af loudnorm=I=-14:TP=-1.5:LRA=11:measured_I=<I>:measured_TP=<TP>:measured_LRA=<LRA>:measured_thresh=<TH>:offset=<OFF>:linear=true -ar 48000 l43_audio_90s_norm.wav
```

### 11.6 交付校验

```bash
# 成片规格
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate,codec_name,pix_fmt,nb_frames,duration -of default=nw=1 l43_promo_1080p30.mp4
# 期望：width=1920, height=1080, r_frame_rate=30/1, codec_name=h264, pix_fmt=yuv420p, nb_frames=2700, duration≈90.0

# 音频规格
ffprobe -v error -show_entries stream=sample_rate,channels,duration,codec_name -of default=nw=1 l43_audio_90s.wav
# 期望：sample_rate=48000, channels=2, duration=90.000000

# 抽帧目检（0s / 15s / 30s / 45s / 60s / 75s / 89s）
ffmpeg -y -i l43_promo_1080p30.mp4 -vf "select='eq(n\,0)+eq(n\,450)+eq(n\,900)+eq(n\,1350)+eq(n\,1800)+eq(n\,2250)+eq(n\,2670)'" -vsync 0 check_%02d.png

# 帧数连续性（PNG 序列方案）
ls frames | wc -l            # 期望 2700
ls frames | head -1; ls frames | tail -1   # f_00000.png / f_02699.png

# 音画同步抽检：在 5 个 Foley 点对比画面事件帧与波形起点，误差 ≤ 1 帧（33ms）
```

### 11.7 时间与磁盘预算

| 项 | 估计 |
|---|---|
| 单帧截图（1920×1080 PNG） | 0.25–0.8s（视机器与降级等级） |
| 2700 帧总耗时 | 约 15–40 分钟（并行 2–4 个浏览器上下文可缩短，但要保证每帧确定性） |
| PNG 序列磁盘 | 约 3000–5000 张 × 0.8–1.8MB ≈ 3–7GB（推荐 image2pipe 方案避免） |
| 成片大小 | 30–80MB（CRF 16） |

### 11.8 失败排查

| 现象 | 先查 |
|---|---|
| 全黑/全白帧 | `?t=` 参数是否被解析；`window.__ready` 是否 true；`#stage` 是否被 `display:none` |
| 文字变字体 | `document.fonts.ready` 是否等待；字体路径 404（检查相对路径） |
| 帧序列错位/重复 | 截图前是否等了两帧 rAF；`seek` 是否被播放循环覆盖 |
| 音频短/长 | WAV 是否 4,320,000 帧；`OfflineAudioContext` 长度参数是否 `Math.round(48000*90)` |
| 音画不同步 | 混流是否用了 `-shortest` 截断；渲染时是否误开播放循环 |
| 逐帧导出画面与浏览器不同 | Playwright viewport/deviceScaleFactor/字体渲染参数是否与验收时一致 |
