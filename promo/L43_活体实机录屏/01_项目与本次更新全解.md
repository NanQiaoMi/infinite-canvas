| 目标用户 | 需要连续探索并迭代视觉方案的图片创作者、设计/运营岗、独立开发者；自备 OpenAI 兼容接口，或走管理员统一配置的服务端模式 | `README.md:117`、`README.md:153`、`README.md:157-163` |

## 6. 技术要点（给懂行的人，每条 ≤ 120 字）

1. **浏览器直连架构**：前端把用户配置的 Base URL 与 Key 直接发给 OpenAI 兼容接口，没有项目自建后端参与（`README.md:117`）；因此 Key 默认落在浏览器本地（`README.md:131`），换设备要重新配置。只有服务端模式改由同源 `/api/relay` 注入真实 Key（`server/src/app.ts:39`）。
2. **异步队列协议**：客户端识别 HTTP 202 表示任务已入队（`image.ts:865,1011`），随后按 `GET /v1/tasks/{id}` 轮询状态、按 `DELETE` 取消（`image-queue.ts:63,115`）；同时向下兼容返回 200 的同步网关，老部署不用改。
3. **工具协议双轨**：模型可走文本 `tool` 代码块，也可走原生 function calling，按渠道在后台选「自动 / 文本 / 原生」（`zh-CN.ts:734-737`）；工具集合含 `generate_image`、`edit_image`、`apply_prompt` 与 8 个 `canvas_*` 画布工具（`zh-CN.ts:982`、`canvas-tools.ts`）。
4. **熔断与并发**：运行时累计本轮已生成图片数，达到用户要求张数即拦截后续生图工具调用（`runtime.ts:284,421,666`）；批量节点用 `Promise.all` 并发（`runtime.ts:558,642`），客户端另设 4 槽位限流（`image/index.tsx:242`）。
5. **诊断数据流**：统一记录 `generation` 与 `model` 两类事件，内存环形保留 + localforage 持久化 500 条 / 7 天（`diagnostics.ts:18-19`），再由 `summarizeDiagnostics`、`summarizeDiagnosticsByDay(…,7)`、`summarizeChannelHealth` 三个聚合函数喂给诊断弹窗与渠道健康检查（`diagnostics.ts:112,141,175`）。
6. **额度与访客（服务端模式）**：服务端按 IP + 浏览器指纹识别匿名访客，额度默认每日 100 张 / 每周 700 张、按自然日与 ISO 周自动刷新（`README.md:162`、`.env.example:11-13`）；数据存 `./data` 的 SQLite 与签名密钥（`README.md:175`）。
